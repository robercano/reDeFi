# 1. Core Architecture & Data Management

## Layered Caching Strategy
**Goal:** Optimize read speeds and reduce RPC load.  
**Approach:** 
- [x] Define a generic `ICacheProvider` interface.
- [x] Implement specific providers: `InMemoryCache`, `IndexedDBCache` (for browser persistence), and `SubgraphCache`.
- [x] Wrap RPC calls in a cache layer. Use block numbers and transaction nonces to automatically invalidate stale entries.

## BlockchainManager Refactor
**Goal:** Prevent RPC bottlenecks and downtime.  
**Approach:**
- [x] Deprecate the single `BlockchainProvider`.
- [x] Create `BlockchainManagerWithProviders` that accepts an array of RPC URLs/Providers.
- [x] Implement a round-robin or latency-based fallback strategy. If a call to Alchemy fails or times out, immediately retry with Infura.

## Real-Time Data Subscriptions
**Goal:** Deliver live updates to frontend applications.  
**Approach:**
- [x] Use `viem`'s `watchBlockNumber` and `watchContractEvent` methods.
- [x] Expose a unified event bus from the SDK (`sdk.eventBus.on('NewBlockMined', callback)`).
- [ ] Implement selective cache invalidation logic inside `DynamoDBCacheService` when `NewBlockMined` is triggered.
- [ ] Build a mock frontend component in `apps/sdk-demo` to verify real-time dashboard updates via the new `useSDKEvent` hook.

## Unified Data Provider (Subgraphs/RPC)
**Goal:** Handle complex queries efficiently while keeping real-time data accurate.  
**Approach:**
1. Define entities in a GraphQL subgraph for historical data (e.g. past trades, yield earned over time).
2. The SDK queries the Subgraph for lists/histories, but falls back to `Multicall3` RPC queries to fetch the *absolute latest* state (balances, allowances) required for transaction building.
